## 模型路径不同，问题也不同

| 坑 | 预防动作 |
| --- | --- |
| Skill安装被当作生成能力就绪 | 分别确认Skill、CLI、Provider/账号、模型输入、素材与预算；工具不在PATH先查项目依赖 |
| 上传成功被当作引用规格通过 | 检查实际文件和选定模式，不依赖画布缩略图判断 |
| 任务状态差异导致重复生成 | 保存原任务身份，先查原结果；已提交时恢复查询/下载；状态不确定时不新增消费。托管路线在请求前写下幂等键，已有任务号就不再提交 |
| H3缺货或隧道故障 | 区分开机、提交、观察、下载阶段；新任务查当前库存/价格，任务后确认停机 |
| 多段声音变成不同人 | 先选统一声音来源；EQ只是局部减轻差异，不能恢复真实同一声纹 |
| 新字幕却保留旧品牌声音/招牌 | 分别验收人物、背景、字幕与完整声音，重要专名听读核对 |
| 提示无字幕仍烧录字幕 | 实际检查，优先换镜头或合理取景；局部底片只用于稳定区域，不默认大黑块覆盖 |
| 后期声音处理出现偏移 | 对比处理前后语句起点、切点、采样数及画面事件，不只看总长 |
| 头尾定格或动作相似 | 导出前并排看首尾及中段，按动作与构图判断重复；不同时间段也可能重复 |
| 口播换人只串联尾帧 | 托管路线每段都用参考图：本人照片、空场景、可选上一段尾帧。只把尾帧当下一帧首帧会让人物和背景漂移；各段口语语言保持同一个 |
| 单帧封面拼接时间戳异常 | 封面与开头统一编码；核对视频流、音频流、帧数和实际前两帧 |
| 中文字体回退成方块 | 核对字体文件及实际名称，并查看实际渲染；家族名正确不等于字体被选中 |
| 原参考没有独立封面 | 说明以哪一帧作构图依据；封面文字与背景不能证明真实项目地点 |
| 成本口径混用 | 分列预算、积分记录、开机用量、估算及结算；托管积分不和 GPU 小时费相加；留存云盘等费用另查 |

## 下次优先执行的四道检查

提交前素材与模式预检 → 生成后人物/信息/声音验收 → 剪辑切点及首尾检查 → 导出后实际画面/声音/流参数检查。具体可勾选条件见[统一工作流](workflow.md#可勾选的交付条件)。

目前未做统一批量成功率、稳定日产量或投放效果测试。总成本需包含筛选、返工、声音和验收，不能只按单次生成价格判断路线。
