# 统一工作流与交付检查

本流程来自五次内容生成测试。根据项目需要使用步骤，不预设固定镜头数、30秒时长或必须出现人物表演。模板字段不是执行脚本；Agent需按实际工具契约读取与填写。

## 目标与输入

记录最终用途、参考、目标人物、准确品牌/项目名、逐字稿、画幅、时长、声音、字幕和封面。未提供原封面时，说明以视频哪一帧作构图参考；项目名文字不证明背景就是目标现场。肖像若有耳机、杯子等不需要的物件，优先准备干净参考。

逐文件检查尺寸、比例、大小、格式和音轨；预检对象必须就是最终引用对象。不同模型的模式、规格与时长上限分别查当前契约。本地布局测试不属于内容生成测试。

## 路线、成本与任务记录

Seedance按视频/图片参考的实际模式生成；H3按当前插件支持的图像条件和短镜头组织；设计图展示以已确认图像和统一声音编排。用户已选路线继续沿用，变化超出授权时才请求决定。

H3 分成两条执行路线。SSH 自建沿用插件、ComfyUI 和实例停机；托管 API 只走 HTTPS 443，适合不能开 SSH 的环境，图片用 Data URL，不先上传到第三方图床。托管任务的幂等键必须在创建请求前写入清单，`taskId` 在响应保存前为空；已有任务号后只查询和下载，失败或取消后的下一次生成使用新清单。积分在提交时预占，失败或取消后释放。默认 768P，1080P 和 2K 要显式指定。积分估算、GPU 小时费和结算分列，见[托管 H3](hosted-h3.md)。

口播换人在托管路线上，每一段都提交多张参考图：本人照片、没有人的空场景，以及可选的上一段最后一帧。三张都用 `reference_image`，不要和 `first_frame` 混在同一次提交里，也不要只把上一段尾帧当成下一段首帧。后一种接法会让人物和背景越来越漂。每一段使用同一个口语语言（`--spoken-language`，或在每段提示词里写同一条约定）。参考图的 SHA-256 按顺序写入清单；任务号还没落下时，恢复会先核对哈希，对不上就不用原来的幂等键。

分别记录每次提交的业务编号、模型/模式、参数、引用文件哈希、平台任务标识、输出路径和费用记录。新任务不继承历史预算或实例。先准备素材再启动GPU；任务后核对停机与用量。区分预算、积分记录、用量折算和结算，不把几种口径相加。

CLI、画布和文件状态不同步时，先查服务端任务及可下载结果；无法确定提交状态时不增加付费任务。仅保留工具契约公开的任务身份，不在持久记录中放访问token、签名URL或临时确认token。

## 四层素材验收

| 层 | 核对项 |
| --- | --- |
| 人物 | 正/侧/背面、帽子眼镜、服装、手部、额外人物、转场错人 |
| 背景信息 | 原招牌、品牌、人名、电话、房号与目标项目是否匹配 |
| 字幕 | 是否烧录、错字、残留文字、实际字体渲染和遮挡面积 |
| 声音 | 完整逐字稿、品牌人名、声音身份、接缝、起点和句子切点 |

音频提取与ASR可初筛，重要专名仍需听读。通过技术检测不等于创意验收通过；工具无法播放听检时明确该项未完成。

## 剪辑表

每镜头记录源文件、原片入点/出点、成片入点/出点、动作、裁切与速度、声音来源和验收结果。先统计筛选后的可用秒数；两条30秒源片不保证40秒可用画面。时长不足时按授权选择补镜头、调整结构或适度慢放，不暗中循环、冻结或拉伸声音。

将开头、中段和结尾缩略图并排看，按机位、人物姿势与动作判断重复。每个切点看相邻帧，复杂转场扩大检查范围；全片半秒抽样不能取代切点检查。字幕、旁白、封面分别管理，修改画面时保留已验收声音。

## 实际导出检查

以下只运行本地工具；`FINAL_VIDEO`和`QA_DIR`需由使用者设置。输出目录必须全新，命令拒绝覆盖。黑帧阈值是检测起点，项目可调整；黑帧检测不识别错人、文字或重复动作。

```bash
set -euo pipefail
export FINAL_VIDEO="<最终MP4绝对路径>"
export QA_DIR="<不存在的QA目录绝对路径>"
mkdir "$QA_DIR"
ffprobe -v error -count_frames   -show_entries 'format=duration:stream=codec_type,width,height,r_frame_rate,avg_frame_rate,duration,nb_read_frames'   -of json "$FINAL_VIDEO" > "$QA_DIR/probe.json"
ffmpeg -v error -i "$FINAL_VIDEO" -f null - 2> "$QA_DIR/decode.log"
ffmpeg -hide_banner -i "$FINAL_VIDEO"   -vf 'blackdetect=d=0.1:pix_th=0.1' -an -f null - 2> "$QA_DIR/black.log"
ffmpeg -n -i "$FINAL_VIDEO" -vf 'select=lt(n\,2)' -fps_mode vfr   -frames:v 2 "$QA_DIR/first-%02d.png"
```

分别比较视频流、音频流与容器时长；可变帧率素材先确定目标帧率，不能直接套固定帧数。严格40秒24fps应为960帧；是否允许音频/容器编码微小余量由项目规定。

封面和开头统一编码，避免一帧独立片段直接拼接造成时间戳异常。实际提取并查看第1帧封面和第2帧正片；一帧24fps只停约0.0417秒，不能作为可阅读片头。发布平台封面选择需单独确认。中文字体需在实际渲染环境看导出结果；普通家族名回退时核对具体字体文件与名称。

## 可勾选的交付条件

- [ ] 所有实际引用文件和模型模式通过预检；已有结果已盘点。
- [ ] 人物、背景信息、字幕、声音分别验收，仍有缺陷已标明。
- [ ] 每镜头有可重建的剪辑表；所有切点与首尾构图检查过。
- [ ] 视频/音频流、帧数、完整解码及检测日志符合项目要求。
- [ ] 实际中文字、第一/最后帧与关键口播已查看听读，或明确未完成。
- [ ] 封面显示时长与发布封面选择符合用途。
- [ ] 原始输出和上一版本保留；成片、脚本与QA对应同一版本。
- [ ] GPU状态已核对；成本口径与未核实费用单独列明。

本仓库可复用的是流程和本地工具。最终发布、投放及新收费任务仍按当前任务授权执行。
